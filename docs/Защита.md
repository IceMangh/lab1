# Алгоритмы и вопросы к защите

**Почему AVL?** В обычном дереве вставка отсортированной последовательности может создать цепочку и дать O(n) на поиск. AVL поддерживает разницу высот соседних поддеревьев не больше 1; высота остаётся O(log n).

**Как выполняется балансировка?** После вставки или удаления на обратном пути рекурсии обновляется высота. При разности высот больше 1 выполняется правый или левый поворот. Если тяжёлый потомок наклонён в другую сторону, сначала поворачивается он: получаются случаи LL, RR, LR и RL.

**Как удалить узел?** Лист удаляется, узел с одним потомком заменяется этим потомком. Для двух потомков берётся максимум левого поддерева; затем балансируются затронутые узлы.

**Почему одинаковые значения не добавляются в дерево?** Это дерево поиска с уникальными ключами. Если ни `a < b`, ни `a > b`, значения считаются одним ключом. Очередь хранит дополнительные приоритет и уникальный номер, поэтому может содержать одинаковые пользовательские значения.

**Какие обходы реализованы?** `LKP` выводит элементы в порядке «левое поддерево — корень — правое поддерево». `LKPThreads` проходит в том же порядке по прошивке, `PKLThreads` — в обратном порядке.

**Что такое прошивка?** Если у узла отсутствует левый потомок, дополнительный указатель ведёт к предыдущему узлу симметричного обхода. При отсутствии правого потомка другой указатель ведёт к следующему. После построения прошивки обход выполняется без рекурсии и вспомогательного стека. В проекте сама прошивка перед каждым обходом строится заново за O(n).

**Почему очередь выдаёт последний элемент при равном приоритете?** Ключ записи — пара `(priority, id)`, `id` увеличивается после каждой вставки. Извлекается максимум дерева, поэтому при равных приоритетах побеждает больший `id`. Это сохранённая семантика `lab2`.

**Почему Top очереди медленнее Top кучи?** Куча хранит максимум в нулевой ячейке массива: O(1). Очередь ищет максимум в AVL по правым ссылкам: O(log n).

**Какие требования к типам элементов?** Дерево и куча используют операторы `<` и `>`, поэтому пользовательский тип должен определять согласованный порядок сравнения. Для вывода нужен `operator<<`. Очередь сравнивает свои записи по приоритету и порядковому номеру, а не по пользовательскому значению.

**Что показывают тесты?** Проверяется результат каждой операции и сохранение инвариантов после последовательностей изменений. Случайные изменения сравниваются со стандартными контейнерами. Ошибки памяти и неопределённое поведение дополнительно отслеживают санитайзеры.
